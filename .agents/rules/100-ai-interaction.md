# AI 交互准则与审查规范

## 1. 回答风格
- **代码优先**：先给出清晰、完整、可直接落地的代码或命令，再跟进简洁精炼的说明，避免空洞冗长的叙述。
- **最佳实践**：当存在多种实现路径时，优先给出推荐的最佳实践，再简明列出备选方案。
- **主动审视**：主动指出涉及并发、数据一致性、资源释放和网络长连接相关的潜在隐患。

## 2. 风险与方案强制约束（核心原则）
> **凡在回答中指出“风险、安全隐患、性能瓶颈、并发冲突、兼容性问题或遗留债务”时，严禁只列风险不给解法。**
> 必须对每一个风险项逐一给出以下三要素：

| 必填项 | 要求与标准 |
|--------|------------|
| **风险是什么** | 一句话说明现象、发生概率与触发条件（必须有代码或链路依据）。 |
| **处理方案** | 至少提供 1 个可落地的解决办法（若选择“暂不处理”，必须写清容忍条件与边界）。 |
| **推荐方案** | 明确标注【推荐】，说明为何选择该方案及相对其他方案的技术取舍。 |

- 存在多项风险时，逐条按“风险 → 方案 → 推荐”展开，禁止在文末一笔带过。
- 涉及修改时，明确列出需**新增 / 修改 / 删除 / 保持不变**的类、协议与接口。

## 3. 代码审查基线
代码生成或修改后，自动核查以下项目：
1. **注释三要素**：字段注释、公共方法 Javadoc、复杂逻辑块“为什么”注释是否齐全（参见 [200-coding-style.md](200-coding-style.md)）。
2. **连接与资源管理**：数据库连接（HikariCP/JDBC）、文件流、Socket 连接必须处于 `try-with-resources` 或严格的 `finally` 关闭块中，防止连接池泄漏。
3. **SQLite 并发安全**：SQLite 不支持高并发多线程并发写，凡涉及写库操作必须关注事务边界与锁机制，严禁死循环轮询锁。
4. **编码规范**：全工程所有 Java、Proto、Shell、SQL、XML 文件必须为 **UTF-8** 编码，文件末尾保留单个换行符。

## 4. 统一 MCP 工具优先原则（强制执行）
> **开发与排查过程中，凡涉及库表数据、Excel 配表、文件沙箱分析、Git 变更审查时，必须优先使用统一 MCP 工具（`game-server-tool`），严禁舍近求远或手写危险脚本。**

1. **查库与数据分析**：
   - 优先使用 `player_db_query`（按 roleId 安全检索）、`local_sql_query`、`local_get_database_info` 查验表结构与数据状态；
   - 严禁自行拼接原生危险 SQL 脚本。
2. **Excel 与数值配表**：
   - 优先使用 `excel_read_sheet`、`excel_describe_sheets`、`excel_format_range` 读取和校验配表数据；
   - 严禁盲猜表头与列索引。
3. **版本审查与日志取证**：
   - 优先使用 `git_log`、`git_show`、`git_commit_files` 追溯历史代码与变更依据；
   - 涉及日志检索时，优先依托统一 MCP 与 copylog 机制进行安全切片。
4. **可视化联动**：
   - MCP 产出的结构化数据如果较为多维或具备分析价值，优先联动 `canvas` 技能生成交互式 HTML 看板交付用户。
