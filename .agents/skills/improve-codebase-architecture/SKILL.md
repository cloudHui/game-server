# Improve-Codebase-Architecture 架构深化与重构技能

## 核心架构原则
- **深模块（Deep Module） vs 浅模块（Shallow Module）**：
  - 深模块：极简的外部接口，内部封装丰富的业务逻辑（高杠杆比）；
  - 浅模块：接口复杂度和实现复杂度几乎一样（如纯透传类、无意义的二次包装层），应当收敛消除。
- **删除测试法（Deletion Test）**：
  - 设想把某个类或方法删除：如果整个系统的复杂度凭空消失了，说明它是一个无意义的透传过渡层；如果其复杂度必须由上层 N 个调用方分摊重写，说明它具备真正的抽象价值。
- **高内聚（Locality）**：
  - 相同生命周期的状态修改集中在一处完成，严禁由调用方分步拼装。

## 执行步骤
1. **代码库探索**：
   - 重点检查 `hub` 模块中整合旧五服务时遗留的胶水代码与适配层；
   - 检查是否存在 Handler 之间直接相互调用，或 Manager 互相循环引用的情况；
   - 检查状态数据是否散落在各个散装类中，缺少集中的事务/原子控制。
2. **输出候选重构清单**：
   对每一个候选点按如下格式汇报：
   - **涉及文件**：精确到具体路径；
   - **架构问题**：指出为什么浅薄或导致摩擦；
   - **拟定方案**：用自然语言说明如何收敛并加深接口；
   - **收益**：如何提高单测便利度与运行可靠性。
3. **征求用户拍板**：
   - 给出推荐顺序，由用户挑选一个最迫切的点实施，切忌未经同意进行大面积破坏性重构。
