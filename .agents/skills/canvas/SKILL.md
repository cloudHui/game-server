# Canvas 交互式看板与数据可视化技能

## 何时使用
- **呈现 MCP 查询数据**：通过统一 MCP（18765 端口）检索出玩家列表、战绩详情、错题统计后，作为最终交付物交付给用户。
- **架构与流程图解**：多服务通信拓扑、桌子生命周期状态机、网络长连接会话生命周期。
- **性能与运维监控**：展示 Hub 进程内存使用、活跃连接数、响应延迟趋势折线图。
- **对局回放与时序推演**：棋牌出牌记录、打牌时序回放控制条。

## 规范与约束
1. **独立工件交付**：看板以自包含的 HTML 格式生成在 Artifacts 独立窗口中，支持全屏展开与交互。
2. **样式体系**：
   - 引入 Tailwind CSS：
     ```html
     <script src="https://www.gstatic.com/antigravity/web/dev/tailwindcss.min.js"></script>
     ```
   - 适配宿主主题语义变量：`bg-[var(--card)]`, `text-[var(--foreground)]`, `text-[var(--muted-foreground)]`, `border-[var(--border)]`，确保暗黑/浅色模式完美适配。
3. **图表库选用**：
   - 关系图与流程图优先使用 SVG 或 Mermaid；
   - 折线图、柱状图、饼图优先使用轻量 Chart.js 或 ECharts（通过内嵌或 CDN 载入）。
4. **禁止空状态（Never render empty states）**：
   - 看板必须渲染真实数据。严禁放占位符、"TODO"、或者全零假图表；若缺失数据，先向用户确认或通过 MCP 查库补齐。

## 工作流步骤
1. **数据准备**：通过 `mcp-db-query` 或日志分析获取原始数据；
2. **构建看板**：使用 HTML + Tailwind 构建网格布局，第一屏呈现最关键指标卡片（Card），随后展开趋势图表与详情表格；
3. **注入交互**：增加基础的筛选下拉框、关键字过滤输入框或分页控件；
4. **交付展示**：输出工件链接，并附带一句话引导用户点击查看。
