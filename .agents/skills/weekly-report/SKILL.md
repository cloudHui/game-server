# 研发周报生成技能

查本人 Git 提交，对照当前对话产出与业务进展，生成标准研发周报。

## 何时使用
- 用户要求 `@weekly-report`、写周报、汇总本周开发进度。

## 前置与工具
- 使用统一 Git MCP 工具：`git_log`、`git_show`、`git_commit_files`、`git_run`；
- 作者自动通过 `git_run` 读取 `config user.name`，不写死固定姓名；
- 日期区间未指定时，以当前日期推算本周（周一至周日或上周五至本周四）。

## 核心工作流
1. **获取本周提交**：
   - 调用 `git_log`（带上 `since`, `until`, `author`, `noMerges=true`）；
   - 对关键提交通过 `git_show` 或 `git_commit_files` 核验修改涉及的模块与业务。
2. **提取对话产出**：
   - 提取会话中已敲定设计但尚未合入分支的改动，或正在联调的内容。
3. **分流归纳**：
   - 已进 Git 的功能点 -> 归入 **已完成**；
   - 方案已确定、分支联调中或测试阶段反馈的问题 -> 归入 **待完成**。

## 输出格式（严格固定标准版式）

```markdown
周报 YYYY/MM/DD-YYYY/MM/DD

已完成：
模块A核心功能实现；模块B接口联调与协议打通；完善服务健康探活与异常捕获逻辑

待完成：
后续工作将集中在测试阶段反馈问题的修复与业务功能联调验收
```

## 规范红线
- 第一行必须是斜杠日期区间的纯净标题；
- 只有【已完成】和【待完成】两大部分，禁止按天罗列、禁止罗列单条 Commit hash；
- 已完成每条用分号隔开，同一模块的若干细节用顿号连接；
- 交付时直接给出纯净周报正文，不夹杂多余技能执行说明。
