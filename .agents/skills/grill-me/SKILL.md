# Grill-Me 方案深度质询技能

## 何时使用
- 用户提出：“我打算把某某模块重构一下”
- 用户提出：“新增一个二人麻将玩法”
- 用户提出：“改造网关的长连接会话路由”
- 用户明确说：“grill me” 或 “帮我审视这个设计有没有坑”

## 执行原则
1. **单步逐问（Ask one at a time）**：
   - 每次交互**只提一个最关键的问题**，等待用户回答后再推演下一个决策分支；
   - 严禁一次性抛出十几个问题的列表轰炸用户。
2. **必带推荐答案（Always provide recommended answer）**：
   - 每个问题必须附带 AI 的专业推荐答案及其权衡原因，方便用户快速拍板（如：“推荐方案 A，因为 SQLite 文件锁在方案 B 下会发生争抢”）。
3. **代码库优先考证**：
   - 如果某个问题可以通过阅读当前代码、Proto 协议或已有的 Manager 逻辑解答，必须自己先查代码，不把已知信息当问题抛给用户。
4. **决策树穷尽**：
   - 重点深挖：异常掉线重连处理、桌子解散与超时退款、并发写锁冲突、前后端兼容性、旧五服务模式下的影响。
5. **达成共识后收敛**：
   - 当决策树的所有关键分支均达成一致后，输出最终技术方案纪要，并征询用户是否开始编写代码。
