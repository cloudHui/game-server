# MCP-Log-Copylog 日志安全切片与取证技能

## 1. 何时使用
- **玩家故障取证**：玩家反馈断线、对局卡死或操作失败，需截取指定日期的服务日志；
- **超大日志分析**：生产/本地日志体量过大，直接查看消耗过高，需定向切片与过滤；
- **关键词追踪**：按指定完整 `roleId`、异常类名（如 `NullPointerException`）或协议 Opcode 提取上下文。

## 2. 核心机制与工具规范

| 机制 / 参数 | 规范与默认行为 | 说明 |
|-------------|----------------|------|
| **源日志保护** | 严格只读流式扫描 | 绝不修改、覆盖或删除任何原始日志文件 |
| **检索工具优选** | 优先 `rg`，无 `rg` 则回退 `grep` | 保持纯数字边界匹配（`\bID\b`），不把 token/设备码当 roleId |
| **日期范围规则** | 按文件名 `yyyy-MM-dd` 匹配 | 起止日期均闭区间包含；空日期默认截取昨天与今天 |
| **落地输出目录** | `log/logs_起日_止日/` 或 `Desktop/log/` | 保持原目录层级与相对路径，不混入临时下载暂存 |

## 3. 门禁与安全红线
1. **纯数字完整边界**：
   - 过滤玩家 ID 时必须保留原始十进制正整数，严格匹配数字边界，防止短数字子串误命中其他 ID。
2. **禁止擅自解压海量历史包**：
   - 历史 `.tar.gz` / `.gz` 优先流式只读读取；若需解压，必须指定独立的只读临时目录，禁止覆盖上层文件。
3. **敏感信息过滤**：
   - 输出的诊断证据中严禁暴露数据库明文密码、玩家 Token 或无关人员隐私数据。

## 4. 诊断闭环工作流
1. **切片获取**：通过 copylog 工具或本地脚本按日期+ID切出目标结果；
2. **证据提取**：提取关键异常堆栈（`Exception in thread...`）与时序前后 5~10 行上下文；
3. **源码对照**：依据堆栈对应的 Java 类名与代码行号，定位具体代码缺陷或并发时序问题；
4. **输出交付**：简要交付 `玩家ID + 覆盖日期 + 异常堆栈证据(文件:行号) + 修复方案建议`。
