# 日汇总（Git + 对话双源对照）

轻量工作回顾：优先查提交和对话，**对照去重后按主题列条**。每条一句，说清做了什么。

## 何时使用
- 用户输入 `@daily-summary`；
- 用户要求：“昨天到今天的提交和对话汇总”、“写个今日工作总结”、“日报”。

## 何时不用
- 正式周报（周报 日期-日期，已完成 / 待完成）改用技能 `weekly-report`；
- 仅查原生 git log / diff 改用技能 `git`。

## 工具链与数据源
1. **统一 Git MCP 工具**（服务：`game-server-tool`）：
   - `git_log`：区间 + author + noMerges；
   - `git_show`：单次提交详情（带 `statOnly=true` 查看文件列表）；
   - `git_commit_files`：文件变动清单；
   - `git_run`：辅助执行只读 git 命令（如 `["config", "user.name"]`、`["status", "-sb"]`）。
2. **对话会话记录**：结合当前上下文真实对话结论，不臆造未发生的事情。

## 执行步骤
1. **确定区间与作者**：
   - 用户说“今天”或“昨天到今天”，从环境获取当前日期；
   - 作者优先通过 `git_run` 获取 `config user.name`，不写死作者。
2. **检索 Git 提交并精读**：
   - 调取 `git_log` 获取指定日期范围与作者的提交记录；
   - 对 message 简略的提交，调用 `git_show` + `statOnly=true` 查看修改的模块与类名。
3. **对照对话去重合并**：
   - 提取会话中“确认了什么根因 / 实现了什么功能 / 优化了什么模块”；
   - 与 Git 提交对应同一件事的合并为一条；
   - 仅讨论未改代码的方案调研，单列为一条；纯日常闲聊/排障询问不计入。

## 输出格式规范（固定）
先一行日期（如 `今天（10/14）：` 或 `昨天到今天（10/13-10/14）：`），下面按加粗主题分类（如 **游戏逻辑**、**MCP工具**、**Bug修复** 等），每项 `-` 列表，每条一句：

```markdown
今天（10/14）：

**MCP 工具链与技能**
- 规范化 MCP 技能体系，补充 player_db_query 索引门禁与 Redis 缓存排查支持
- servertool 模块完成 Maven 化架构整合，剥离遗留 Swing 桌面代码

**网关与通信**
- 优化 UserService 登出与连接管理时序，完善心跳监听
```

## 交付规范
- 交付给用户的内容中**禁止出现 Git commit hash**，禁止成段冗长罗列代码 diff；
- 保持语言简练，客观真实，直奔业务与功能产出。
